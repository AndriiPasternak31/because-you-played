A clean catalogue, damaged on purpose

A recommender is only tested by data that misbehaves. This catalogue is fictional. Every game starts as a clean, known record, and seeded code then damages it the way real supplier feeds are damaged. Because the damage is recorded, every defect can be counted and every answer checked.

How one game is made

Three steps. Code makes every decision and does all the damage. The model does one job in the middle: writing the prose.

  1. Code · seeded

    1. Plan

    Decides what the game is before any text exists.

    • Studio, themes and mechanics from a fixed list of 24 labels
    • Facts: RTP, volatility, grid, bet limits, release date
    • Which brands offer it, and with what status
    • Which defects its raw row will carry
  2. Model

    2. Write

    Writes a title and a description that express the plan.

    • One exact quote per planned theme and mechanic
    • Output must match a strict schema
    • A bad answer is rejected and stored, never repaired
  3. Code · seeded

    3. Damage

    Turns the clean record into what a feed would deliver.

    • Drops, misspells and pollutes tags
    • Removes or replaces descriptions
    • Reformats facts per studio
    • Records exactly what was lost

The model never writes a fact or an availability record. Change every word it wrote and no fact, no offering and no defect moves. A test proves this.

A model answer is rejected when it

  • quotes text that is not in its own description
  • mentions a mechanic the plan did not assign
  • states a number or a volatility the plan did not supply
  • uses a name that belongs to a real game, studio or brand
  • breaks a title rule, or comes too close to an existing title
  • is refused, cut short or malformed

What is in the repository, and who may read it

The clean truth is kept so that evaluation can tell a label that was recoverable from one that was unknowable. The pipeline and the service are never allowed to read it.

Hidden: generator and evaluation only
  • truth.games.jsonl100 games as they really are, with the quote behind each label

Reports anyone can read
  • mess-report.jsonRow counts per kind of mess

Rebuilding from the stored answers needs no API key and gives the same bytes every time. A stored answer that is damaged, or that no longer matches the code that asked for it, stops the build and names the file.

What this catalogue cannot tell you

  • It is easier than real supplier copy. One model wrote every description, and each one states its planned mechanics plainly.
  • The truth is not independently labelled. Code checks that each quote is word for word in the description. It cannot check that the quote is good evidence.
  • "Recoverable" is mechanical. It means a quote, a tag or a title word survived. It is a diagnostic, not a human judgement.
  • Names are invented and were searched for, not legally cleared.
  • Slots only, one feed shape, one jurisdiction per brand.

Figures are read from the committed data. An independent reviewer recounted every kind of mess from the raw rows without using the generator's code, and all counts matched.
