Because You Played · evaluation

Four decisions before the evaluation runs

A pass mark only means something if it is fixed before the results exist. These four choices are yours: the agents are blocked from writing the file that holds them. Each section shows the evidence, then the choice. The last section collects your answers.

Question one

Is enrichment safe to automate?

Are the labels it adds right, can each be traced to a quote, and does it stay silent when the record gives it nothing to go on?

Question two

Does it earn its place?

Do recommendations built on enriched records rank related games better than recommendations built on the raw text alone?

Decision 2

The answer key

The evaluation needs something to score against. The generator already knows what every game is and exactly what evidence each raw row lost. That record can be the answer key, if it is used with care.

491 planned labels across the 104 raw rows
403 still present in a tag 51 only in the description or the title 37 with all evidence removed
  • 454 recoverable labelsThe evidence survives, so enrichment should find them. This is the denominator for recovery.
  • 37 unknowable labelsThe evidence was removed. These count neither for nor against the model: unknown is not wrong. They sit in 13 fields where the correct answer is to say nothing.
  • Labels the plan never assignedIf the model asserts one, it is either a mistake or a fair reading of the text. Only a person can tell, and that is the part that needs you.

The question, word for word, as a person would be asked it

Here is the text a game supplier sent for one slot game.

"{the description, tags and title exactly as delivered}"

Label: {name}. It means: {one-sentence definition}.

Does the text support this label? Answer yes, no or unclear. If yes, copy the exact words from the text that support it. Otherwise leave the quote empty.

The question never says whether the pipeline or the plan made the claim, and the list is shuffled. A second question of the same shape covers recommendations: "A player has just played this game. Would this other game be a reasonable 'you might also like'?"

Four calls, about five seconds each, a fraction of a cent. The last row is the vague label from decision 1 behaving as expected: the plan did not call this game an adventure, and a reader could argue either way.

One thing to know before choosing the model as reviewer

The catalogue text, the enrichment and this reviewer would all come from the same vendor's models, and related models can share blind spots. The fix is cheap: you answer six of the same questions yourself, without seeing the model's answers, and the report states how often it agreed with you. Two minutes, and the reviewer has an anchor.

For matching: which games count as related · 4,950 pairs
137 strong: a shared theme and two shared features 531 related: a shared theme and one shared feature or win system 841 weak: a shared theme only, or two shared features 3,441 unrelated

Relatedness is worked out by rule from the plan, not by reading. The test is simple: for a given game, a strong or related game should rank above an unrelated one.

Decision 3

The pass marks

Move a slider to see what the mark means in plain counts. The starting positions are my recommendations.

One recommendation changed after reading the data

I first suggested a recovery mark of 0.60. But 403 of the 454 recoverable labels, 89%, are still sitting in a tag, so a simple synonym table would pass 0.60 without reading a word. The mark is now 0.85 overall, with a separate mark for the 51 labels that can only be found by reading.

The same sliders, inside the product

The console gets this icon beside the evaluation result. It opens a panel with these sliders, set against the numbers the evaluation actually measured. Move one and each mark turns green or red at once, so anyone can see how much room a result had.

The one constraint: the sliders explore, they do not decide. The committed marks stay locked and show as a tick on each slider. The release gate reads only the committed file, and the panel says so. Otherwise a pass mark could be moved after the result is known, which is the thing the commit order exists to prevent.

Decision 4

What gets compared, and what ships

"Enriched against raw" is one comparison with a yes or no at the end. It cannot say why. Since 89% of the labels are already sitting in tags, the sharper question is: what does each step add, and what does it cost?

The ladder: four versions of every game's text, run through the same test

  1. Raw text no model · no codeTitle, description and tags exactly as delivered. The baseline everything has to beat.
  2. Synonym table no model · a short lookupTags mapped onto the fixed labels by a plain table: "Locked Wilds" becomes sticky wilds. Shows how far ordinary code gets.
  3. Model enrichment, every game one model call per gameThe model reads the whole record and adds labels with quotes. The step the brief asks for.
  4. Model enrichment, only where the record is thin a call for roughly a third of gamesThe table handles records with good tags. The model is called only for records where reading is needed. Cheaper, and closer to how this would run in production.

The rule that decides what ships, fixed in advance

Ship the simplest version that scores within a small margin of the best. If the synonym table matches the model, the table ships and the README says the model was not needed here. That is a result worth showing: the tool was judged on evidence, and the cheaper one won.

Margin for "as good as the best"

0.02

With about a hundred games, small differences are noise. The margin says how small a gap is treated as a tie, and a tie goes to the simpler version.
