Because You Played

A related-games recommender: “Because you played X, you might like…”. It is being built by AI coding agents working under written rules, with every change checked before it is merged. This page shows how far the build is and how it is run.

How the work is run

The same loop for every change. The agents do the building and the checking. The decisions stay with me.

  1. 1

    Plan

    Spec and evaluation design first, challenged by a second model.

  2. 2

    Brief

    Each agent gets the goal, the context and the bar for done. Never the steps.

  3. 3

    Build

    One issue, one branch, one pull request, with the checks that prove it.

  4. 4

    Break

    A fresh agent runs the change and tries to make its claims false.

  5. 5

    Decide

    I merge. I set the evaluation pass marks. I judge the interface.

Three rules the product cannot break

Facts

The model never writes facts or availability.

Serving

No model call while a request is being served.

Availability

Unavailable games are removed before any ranking.

Tools: Claude Code agents build and review. A second model from another vendor gives independent second opinions on decisions. OpenAI models write the fictional catalogue and will do the enrichment and embeddings.

A row can carry several kinds of mess, so the bars do not add up to 104. Thirteen of the twenty kinds are shown. Every game, studio and brand name is invented.

  • The whole catalogue rebuilds byte for byte from stored model responses, with no API key.
  • A damaged or out-of-date stored response stops the build and writes nothing.
  • The model's text cannot change a fact or an availability record: both come from code.

What checking has caught so far

A review that only reads the change tends to produce opinions. These were found by running things, and each has a fix.

Found by running it · documents

The first pull request's own evidence failed when run from a fresh copy of the repository.

Fixed. The checks now run from a clean copy and depend on nothing outside it.

Found by reading · documents

Two documents disagreed about whether the catalogue was built.

Fixed. Each part's status now lives in exactly one file, and the others link to it.

Found in the output · catalogue

The first full run kept drifting to the same subjects: six badger games in the first 58.

Fixed. Each game now gets a seeded setting and title pattern, and the catalogue was regenerated.

Found by reading · tests

The test command could pass by finding no tests to run, and one proof stayed green when the thing it proves was broken.

Fixed. The command now fails when nothing was tested, and the proof now fails when it should.

Found by running it · catalogue

A damaged stored response stopped the build correctly, but the error did not say which file was broken.

Fixed. The error now names the broken file, and two new tests hold that.
